# Codex初案 — 祭典終端巨人「ティウ」

## 1. 現在のゲーム構造の要約

- React 19 + React Three Fiber + Three.js + Vite。ゲーム状態は `src/engine/sim.js` の単一 `sim`、固定更新は `src/engine/step.js`。
- 既存4ボスは `src/data/bosses.js` の定義と `src/engine/bosses.js` の状態機械で管理され、対応建物の65%破壊で出現する。戦闘時は `arena.js` がNavMesh上の閉鎖領域を作る。
- 4ボスの撃破数・順序・報酬は `bossProgress` にあり、`save.js` で保存済み。ラスボス条件に直接再利用できる。
- すべての攻撃は `targets.js::damageTarget` へ集約される。敵、既存ボス、建物、残骸、ボス小物への分岐を保ったまま部位判定を追加できる。
- プレイヤーは地上NavMesh移動と `webswing.js` の独立した空中移動を持つ。通常接地は地形高さへ補間するだけで、動く足場への追従は未実装。
- カメラはプレイヤー胸部を追従し、ベイク済み遮蔽で距離を詰める。距離上限16mは36m級ボスには不足する。
- 既存ボス表示は独自の手続きアニメーション。ラスボスには実Mixamoクリップを使う独立描画モジュールを追加する。
- HUDはボスHP、技、モバイルでも押せるアクションボタンを持つ。一方、移動ジョイスティック自体は現状未接続なので、ラスボス実装と同時に最低限のタッチ移動を補完する必要がある。
- 現在の `npm test` は全項目通過。`npm run build` も成功する。既知警告は約1.45MBの単一JSチャンクと、`save.js` の無効なdynamic importによる分割警告。

## 2. `bosstiu` の確認結果

Blender 4.4.3で全FBXを実際に読み込んだ。

| ファイル | 内容 | 実測尺（30fps換算） |
|---|---|---:|
| `T-Pose.fbx` | 本体メッシュ + Mixamo骨格 | 0.067秒 |
| `Walking.fbx` | 通常歩行 | 1.900秒 |
| `Swagger Walk.fbx` | 威圧的な歩行 | 5.567秒 |
| `Stomp.fbx` | 踏みつけ | 3.733秒 |
| `Throw Object.fbx` | 両腕主体の投擲 | 9.733秒 |
| `Swatting Bugs.fbx` | 身体表面を払う動作 | 13.333秒 |
| `Two Handed Sword Death.fbx` | 大きく崩れる死亡 | 4.800秒 |

全FBXは同じMixamo 41ボーン構成。`T-Pose.fbx` の本体は46,895頂点、93,790ポリゴン、1メッシュ、無材質。サイズは約0.02単位で、FBXのcm→m変換が必要。`output/boss_textured.glb` は同一形状の写真投影テクスチャ版（2048²、11MB）だが骨格を持たない。最終素材は、T-Pose側のスキンと全アニメーションを保持し、既存の焼き込みテクスチャを同一トポロジへ移したGLBをBlenderで生成する。

## 3. 一文コンセプト

倒した4守護者の力を吸い上げて町そのものより巨大化した「祭典終端巨人ティウ」の一歩を止め、膝を折らせ、動く身体をウェブと瓦礫で登り、四肢を壊して胸の祭核を地上へ持ち帰る“敵・移動ステージ・エンディング”一体型の決戦。

象徴的な体験は、最終フェーズで胸核を破壊したプレイヤーが倒れ始めた巨人の身体を逆走して手のひらへ飛び移り、その手に安全に地上へ下ろされる「最後の降下」。死亡演出で操作を完全には奪わず、登った身体を自分で降りることで戦いを締める。

## 4. 4ボス撃破から登場まで

1. 4体目撃破時、4報酬アイテムが空へ光柱を出し、町中央の広場へ収束する。
2. 通常敵を停止し、5秒の安全時間を設ける。プレイヤー操作は維持する。
3. 町の遠景外から巨大な頭部が上がり、既存4ボス（3〜4m）と建物を足元の尺度として同一画面に映す。
4. ティウが広場外周へ一歩踏み込み、衝撃波で既存の破壊可能瓦礫を上げる。専用アリーナを半径52mでロックする。
5. 初回は約9秒、再戦は2秒へ短縮可能。攻撃判定は登場完了後2秒まで無効。

## 5. 巨大さの見せ方

- 表示身長36m。既存最大ボス4mの9倍、平均比で約10倍。
- カメラは登場時だけプレイヤー、建物、足、頭を同時に入れる最大30mの引きへ滑らかに遷移。
- 足音は低域、足元の円形粉塵、0.25秒遅れて届く衝撃波の三段構成。
- 通常攻撃の射程では足首しか届かず、身体を登ることで初めて上半身へ攻撃可能になる。

## 6. 身体へ乗る方法

主経路は「踏みつけを誘導して片膝をつかせ、地面についた前腕または太腿を坂として登る」。ウェブ習得済みなら肩・腰の発光アンカーへ短縮できる。未習得・タッチ端末でも前腕の自動よじ登り判定と瓦礫スロープで必ず乗れる。透明エレベーターは使わない。

## 7. 身体上の移動ルール

- 足場は足、すね、太腿、手、前腕、上腕、肩、背中、頭頂の9個以内。
- 各足場は対応ボーンのワールド変換へ追従する低ポリゴンOBB/カプセル。見た目のSkinnedMeshをColliderにしない。
- 傾斜45度以下は歩行、45〜65度は速度低下、65度超は滑落。ただし攻撃予兆中は縁のグリップ帯で1秒耐えられる。
- 足場境界では最も高い接触面を選び、1フレームのヒステリシスを持たせて頻繁な付け替えを防ぐ。

## 8. ボス上で安定して立たせる仕組み

`finalBossPlatform` に前フレームと現フレームのMatrix4を保持し、接地プレイヤーへ差分変換を先に適用してからローカル入力を解決する。回転差は足場中心を軸に位置へ適用し、プレイヤー自身のyawへは緩やかに30%だけ加える。急変は1フレーム0.9m／12度でクランプし、超過時は安全なローカル位置へスナップする。ジャンプ中は最後の足場速度を慣性として渡し、接地追従を解除する。

## 9. 部位破壊システム

- オフライン生成時に、スキン頂点の支配ボーンから部位メッシュを分離する。ランタイムBooleanは使わない。
- 各部位は `intact → wounded → broken`。50%で傷発光と焦げデカール、0%で対応外装を非表示にし、軽量な断面キャップと最大4破片へ差し替える。
- 攻撃命中点をボスローカル座標へ変換し、球/カプセル部位Colliderのうち最短のものへダメージを渡す。
- 本体HPは部位ダメージの一定割合のみ減る。攻略必須部位を順不同で壊せるが、胸核は条件を満たすまで無敵。

## 10. 壊せる部位一覧

左すね、右すね、左前腕、右前腕、背中の四祭導管、頭部の視界冠、胸の祭核。手足末端の完全分離は足場消滅事故を避け、外装欠損 + 機能停止として見せる。前腕破壊後も内側の骨格足場を残す。

## 11. 部位HP・状態変化・攻撃変化

| 部位 | HP | 破壊時の見た目 | 行動への因果 |
|---|---:|---|---|
| 左すね | 420 | 脛外装が欠け発光亀裂 | 左踏みつけ停止、旋回速度-25%、膝つき時間+3秒 |
| 右すね | 420 | 同上 | 右踏みつけ停止、歩行速度-25%、膝つき時間+3秒 |
| 左前腕 | 360 | 袖外装欠損、断面発光 | 左払い範囲-50%、左腕が恒常的な登攀路になる |
| 右前腕 | 360 | 同上 | 投擲数3→1、右腕が恒常的な登攀路になる |
| 四祭導管 | 各180 | 対応色の管が破裂 | 対応する4ボス由来攻撃を1つずつ停止。4本破壊で胸核露出 |
| 視界冠 | 300 | 頭の光輪が半壊 | 追尾精度低下、予兆時間+0.45秒 |
| 胸の祭核 | 900 | 段階亀裂→完全破砕 | 最後の一撃と死亡シーケンス開始 |

## 12. 全フェーズ構成

- P0「目覚め」: 登場、安全時間、尺度提示。
- P1「一歩を止める」: 地上で左右のすねを狙う。片脚破壊で膝つきし、身体へ乗る。
- P2「身体は戦場」: 前腕・肩・背中を巡り、4本の祭導管を順不同で破壊する。
- P3「空を見下ろす」: 頭部の視界冠を壊して胸へのルートを開き、露出した祭核と戦う。
- P4「最後の降下」: 死亡アニメ中に頭→肩→腕→手へ移動。失敗しても手が救助し、死亡扱いにはしない。

## 13. 各フェーズの目的と攻略

- P1: 足の踏み位置を読んで回避し、攻撃後の停止中にすねを壊す。片脚で進行可、両脚で以後が易化。
- P2: 払い予兆に対してグリップ帯へ寄るか別足場へ移る。4導管は既存ボス色とアイコンで対応が分かる。
- P3: 頭部攻撃を止めると胸へ届く手のひらルートが現れる。核の脈動間隔を見て攻撃と退避を交互に行う。
- P4: 12秒以内に発光足跡を逆走。操作可能な余韻で、落下時も敗北させない。

## 15. 予兆・回避・反撃機会

- 踏みつけ: 1.25秒前に足裏色、地面円、カメラの小引き。円外へ回避後2.8秒すねが停止。
- 投擲: 2秒かけて瓦礫を拾い、影で着地点表示。影外へ移動し、右前腕へ反撃。
- 虫払い: 払う側の肩→肘→手の順に0.9秒発光。反対側またはグリップ帯へ移り、通過後1.8秒腕へ反撃。
- 身震い: 足場縁が黄→赤。ジャンプではなくグリップ帯へ入る。両すね破壊済みなら振幅半減。
- 四祭反響: 導管色と既存攻撃の地面予兆を再利用。対応導管破壊で永久停止。
- 視界走査: 頭の向きと床上の細線を1.3秒表示。背中側へ回る。冠破壊後は速度低下。
- 核鼓動: 1.1秒前から核と安全帯を交互点滅。波直後の2秒が攻撃機会。

## 17. カメラ設計

- 地上P1は距離12〜28m、身体上P2/P3は7〜16mへ状態別に滑らかに変更。
- 攻撃予兆時は0.4秒だけ10〜20%引く。`reducedMotion` 時はシェイクと強制引きを弱める。
- カメラからプレイヤーまでを、巨大ボスの簡略球/カプセルへ線分判定し、内部に入る直前まで距離を短縮。
- ロックオンは行わず、現在攻撃可能な部位へ弱いカメラ誘導（最大毎秒8度）のみ。

## 18. 落下・復帰・即死・チェックポイント

- 高所から落下しても即死させない。ボス足元へ達する前に、最寄りの壊れていない手/膝の復帰点へ光の糸で引き戻す。
- P2開始時とP3開始時にチェックポイントを保存。リロード時は同フェーズ冒頭・既破壊部位を復元。
- 埋まり、NaN、足場の瞬間移動、アリーナ外を検知したら直近安全ローカル点へ復帰。
- プレイヤー死亡では戦闘を中断せず、同フェーズ開始点へ4秒後に戻し、ボス部位進行は保持する。連続失敗時は予兆+20%。

## 19. UIと弱点表示

- 全体HPの下に7部位の小ゲージ。現在狙える部位だけ彩度を上げる。
- 画面中央に「左すねを攻撃」「腕が地面についた—登れ」の1行目的表示。
- 部位上には距離で薄れる輪郭リング。色だけに依存せず形状アイコン（脚/腕/導管/冠/核）を併用。
- モバイルでは目的と現在部位のみ常時、全一覧は折りたたむ。

## 20. 音・振動・画面効果

- 既存BGM管理を拡張し、P1低音、P2打楽器追加、P3旋律追加のレイヤーを切り替える。素材欠損時は既存bossChaseへ戻す。
- 足音、導管破壊、核鼓動は別音量。Web Vibration対応端末のみ短い振動を使い、設定/非対応時は無効。
- reducedFlash/reducedMotionを全ラスボス演出に適用する。

## 21. 死亡演出

核HP0で即撃破確定せず、死亡シーケンスへ移る。導管の光が町へ戻り、`Two Handed Sword Death` で安全方向へ崩れる。プレイヤーは発光ルートを手まで降りる。着地後に巨人の指が開き、4報酬色の粒子が空へほどけ、環境音だけが2秒残る。その後に撃破確定・セーブする。

## 22. 撃破後のゲーム状態

- `finalBoss.defeated=true`、初回撃破時刻、破壊順を保存。
- 通常敵とアリーナを復帰。4ボスの撃破状態は維持。
- 中央広場に再戦用の小さな「祭核の記憶」を置く。再戦はセーブ進行を上書きせず、撃破済み報酬を重複付与しない。
- エンディングメッセージ後も町を自由探索できる。

## 23. PC・スマホの性能対策

- 本体93,790ポリゴン、41ボーン、2Kテクスチャ1枚を上限。追加部位は合計12 draw calls以内。
- Colliderは最大9足場 + 7部位 + 1本体。SkinnedMesh raycastは攻撃時だけ、通常接地には使わない。
- 破片はPC最大48、mobile/low最大20、寿命8秒。パーティクルはPC120、mobile40。
- 巨人の影は1枚のblob/簡易投影。SkinnedMeshの動的影はPC highのみ、mobileは受影もしない。
- 60m以遠はアニメ更新30fps、画面外は15fps。P1地上では上半身部位マーカーを間引く。

## 24. 技術的リスク

1. 写真テクスチャ版が非スキン: 同一46,895頂点トポロジを検証し、T-PoseスキンへUV/材質を移す。失敗時はT-Poseへ単色+発光外装。
2. Mixamo root motion: 書き出し時にHips水平移動を除去し、ゲーム座標との二重移動を防ぐ。
3. 動く足場境界: 接地IDのヒステリシスと差分クランプを実装。失敗時はボス攻撃中の足場回転を制限。
4. 単一メッシュ欠損: Blenderでボーン重み別に事前分割。分割品質が悪ければ本体は残し、外装・発光・煙で欠損を表すがゲーム判定は維持。
5. 既存弾のボス部位命中: 現在の本体XZ円判定より前にラスボス専用3D部位判定を通す。
6. マルチプレイ: 初期完成はホスト権威で部位状態をsnapshotへ追加。ゲストの足場補間はホスト状態から再構成する。
7. モバイル移動未接続: 既存 `touch.move` に画面左ジョイスティックを接続する。

## 25. 最小・標準・理想版

- 最小: 36mモデル、脚→背中→核の3フェーズ、5足場、4部位、3攻撃、落下復帰。
- 標準（採用候補）: 本文の4フェーズ、9足場、7系統部位、7攻撃、実クリップ、部位欠損、セーブ、PC/スマホ、死亡降下。
- 理想: 町の破壊順を攻撃構成へ反映、音楽の動的レイヤー、マルチプレイで別部位同時攻略。標準完成を遅らせる場合は入れない。

## 26. 実装順序

素材統合→独立状態機械→4ボス後出現→巨大描画→簡略Collider→動く足場追従→攻撃1本の縦切り→部位判定→破壊差し替え→全フェーズ→死亡降下→セーブ/UI/モバイル→ネット同期→回帰/性能。

## 27. 未確定事項

- 写真テクスチャGLBとT-Pose FBXの頂点順が完全一致するか。
- `Swatting Bugs` の左右払いに使える正規化時間区間。
- 36mモデルを町中央へ置いた際の建物・カメラ・アリーナ境界との実測干渉。
- ラスボス専用音源の有無。無ければ既存BGMを演出変化付きで再利用する。
- マルチプレイで身体上に複数プレイヤーが立つ場合の許容精度。
